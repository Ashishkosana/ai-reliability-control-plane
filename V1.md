# V1 design — AI reliability control plane

This is the laboratory design. Implementation follows this file, not a vendor architecture diagram.

## Question

What fails when every feature calls a model SDK directly, and what is the thinnest control plane that makes those failures visible and blockable?

## State machine (one `complete()`)

```text
load feature
  → missing: policy error
  → killed: kill_switch (no provider)
reserve budget (atomic increment if count < cap)
  → store down + fail_closed: store_down (no provider)
  → store down + fail_open: unmetered=true, continue
  → cap hit: budget (no provider)
load prompt version
call provider
  → retryable error: retry once
  → still failing and fallback configured and not timeout: one fallback call
record spend if ok
write trace (best-effort; loss is a metric)
return result
```

There is no queue on this path. Distribution is “N application processes, one Postgres.”

## Data

- `aicp_features` — live pointer at a prompt version, kill switch, fail-closed, budget caps
- `aicp_prompt_versions` — immutable `(feature, version, body)`
- `aicp_budgets` — `(tenant, feature, window_start)` with `request_count` and `spent_usd`
- `aicp_traces` — hash + preview, tokens, cost, latency split, retry/fallback/unmetered flags
- `aicp_eval_cases` / `aicp_eval_runs` — deterministic checkers
- `aicp_promote_events` — accepted and refused promotions

## Choices already made

| Topic | V1 |
| --- | --- |
| Insertion | In-process library + HTTP adapter |
| Store down | Per feature, default fail closed |
| Budget | SQL `UPDATE … WHERE request_count < cap` |
| Eval | Offline gate on promote; no LLM judge |
| Payloads | Hash + truncated preview; full text is a flag |
| Provider | Fake only. Measures the plane, not OpenAI. |

## Non-goals

Chat UI, RAG, agents, semantic cache, human review queues, multi-region, Kubernetes.
